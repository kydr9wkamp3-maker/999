## 1. МИССИЯ

CHROMECORE X — быстрая, красивая камера для Android, в которой прямо в видоискателе есть:

- нормальная камера (фото, видео, Pro-режим, зум, фокус, экспозиция, вспышка, HDR/ночь);
- живые фильтры и эффекты (глитч, хром, VHS, пиксели, дизеринг, RGB-split и так далее) — видны в превью, попадают в фото и видео один в один;
- AR как в TikTok / Instagram / Snapchat: маски на лицо, стикеры, **GIF и анимированные стикеры на лице и в кадре**, замена фона, жесты рукой;
- визуальный редактор эффектов в стиле TouchDesigner (ноды) и таймлайн-слои в стиле After Effects (ключевые кадры, режимы смешивания);
- неразрушающий редактор фото/видео;
- Device Lab — честный отчёт о железе и диагностика.

Интерфейс простой: открыл — сразу видоискатель, всё остальное в один жест. Стиль **Obsidian Chrome** (см. §6).

Целевое устройство: Motorola Moto G85 5G (Snapdragon 6s Gen 3, Adreno 619, 8 ГБ, основная 50 МП Sony LYTIA 600 с OIS, ультраширик 8 МП, фронтальная 32 МП, pOLED 120 Гц). Бюджетный GPU: **производительность — фича, а не опция** (см. §10).

Невозможно сделать всё за один заход. Делай по этапам из §8, но **после каждого коммита приложение собирается и запускается**. Недоделанное прячется за feature-флагом и не показывается в UI.

## 2. НЕРУШИМЫЕ ПРАВИЛА

1. **Один этап за раз.** Следующий начинается только после PASS предыдущего (доказательства — §11).
2. **Читай прежде чем писать.** Перед правкой открой файл целиком. Никаких слепых перезаписей, дублирования `@Composable`, угадывания имён символов.
3. **Не выдумывай API и версии.** Каждую библиотеку и версию сначала проверь (§3.2). Если не уверен — найди в документации или в исходниках зависимости.
4. **Никакой фальшивой зелени.** Запрещено: `continue-on-error`, `|| true`, `if: always()` на проверках, `-x test`, `-x lint`, пустые `catch`, `assertTrue(true)`, пустые `TODO`-кнопки в UI, `abortOnError=false` без записанной причины и срока.
5. **Честность документации.** README/ARCHITECTURE/BUILD_GUIDE описывают только то, что есть в коде. Будущее помечай `PLANNED`. Любое изменение кода = обновление `docs/PROGRESS.md` в том же коммите.
6. **Каждый коммит оставляет CI зелёным.** Если фича не готова — флаг в `FeatureFlags.kt`, по умолчанию выключен.
7. **Не лечи симптом.** Не меняй настройки наугад. Сначала первопричина (§3.1).
8. **Приватность.** Вся обработка кадров на устройстве. Камера/микрофон — только по явному разрешению. Никаких секретов, ключей API, keystore в git.
9. **Не ломай рабочее.** Перед изменением общей части (конвейер, тема, навигация) запусти все тесты и запиши, что именно зависит от этой части.
10. **Если нужна помощь пользователя** — это только то, что ты физически не можешь сделать (проверить вспышку на телефоне, принять решение по дизайну). Формулируй конкретно: что сделать, что прислать, зачем.

## 3. ПРОТОКОЛ САМОПРОВЕРКИ И САМОЛЕЧЕНИЯ

### 3.1 Цикл исправления ошибки (CI красный, краш, баг)

1. **Получи лог сам**: `gh run view <id> --log-failed`; для краша на устройстве — `adb logcat -d -b crash`; для эмулятора — артефакт `logcat.txt` из CI.
2. **Найди ПЕРВУЮ настоящую ошибку**, а не последнюю в каскаде (в Gradle ищи первое `error:`/`e: `/`FAILED`/`Caused by`).
3. **Классифицируй**: зависимости / AAPT2-ресурсы / компиляция Kotlin / Compose / R8 / lint / тест / GLSL-шейдер / рантайм-краш / права / производительность.
4. **Ищи ответ**: точная строка ошибки + версии (AGP, Kotlin, CameraX) в поиске; сначала официальные доки и issue-трекеры библиотек (developer.android.com, issuetracker.google.com, GitHub Issues проекта), потом форумы. Проверяй дату: решение старше текущих версий — подозрительно.
5. **Сформулируй гипотезу в одной строке** и запиши в `docs/PROGRESS.md` («Гипотеза: …»).
6. **Минимальная правка**, пуш, дождись CI.
7. **Не помогло — другая гипотеза.** После 3 неудачных ГИПОТЕЗ: `git bisect` от последнего зелёного коммита, минимальный репро в отдельной ветке, сравнение с последним зелёным diff. Только потом — вопрос пользователю, и вопрос конкретный, с выжимкой того, что ты уже проверил.
8. **Запиши в `docs/KNOWLEDGE.md`**: `проблема → причина → решение → источник (URL) → дата`. Перед новой задачей читай этот файл, чтобы не наступать на те же грабли.

### 3.2 Исследование перед использованием незнакомого

Перед добавлением библиотеки/API:

- открой официальную страницу и release notes;
- проверь, что версия реально существует (Google Maven `maven.google.com`, Maven Central) и совместима с AGP 8.7.3 / Kotlin 2.0.21 / compileSdk 35 / minSdk 26;
- проверь размер APK-вклада и лицензию (Apache-2.0/MIT/BSD — ок; иное — спроси);
- добавь в `gradle/libs.versions.toml` (никаких версий в `build.gradle.kts`);
- запиши решение в `docs/DECISIONS.md` (ADR: контекст → варианты → выбор → почему).

Если веб-поиск недоступен — скажи об этом прямо и работай только с тем, что можешь проверить в коде/документации в репо.

### 3.3 Самопроверка перед каждым коммитом

```
bash scripts/preflight.sh
./gradlew compileDebugKotlin testDebugUnitTest lintDebug assembleDebug   # если есть локальный SDK
```

Затем пуш и ожидание CI. «Готово» = все джобы зелёные + артефакт существует + критерии этапа выполнены.

## 4. ИНФРАСТРУКТУРА ПРОВЕРОК (построй на этапе S0.2–S0.3)

### 4.1 CI (`.github/workflows/android.yml`), джобы

| Джоба | Что делает | Блокирует |
|---|---|---|
| `preflight` | `scripts/preflight.sh` (секунды) | да |
| `build` | `compileDebugKotlin`, `testDebugUnitTest`, `lintDebug`, `assembleDebug`, проверка APK, upload `chromecore-x-debug-apk` | да |
| `shaders` | валидация всех `*.frag`/`*.vert` через `glslangValidator` (`apt-get install glslang-tools`) | да |
| `emulator-smoke` | эмулятор (например `reactivecircus/android-emulator-runner`, API 34, виртуальная сцена камеры): установить APK, выдать права, запустить, снять кадр, проверить запись в MediaStore, выгрузить `logcat.txt` и скриншоты | да, когда стабилен (до того — явно записано в PROGRESS, какой срок) |
| `release-debug` | публикует APK в GitHub Release (prerelease `latest-debug`) — пользователь скачивает APK с телефона одной ссылкой | нет |

Проверяй актуальные версии actions и параметры эмулятора по документации, а не по памяти.

### 4.2 `scripts/preflight.sh` — обязательные проверки

Уже есть: дубли `@Composable`, `tools:` без `xmlns:tools`, фальшивая зелень в workflow, пропуск проверок в Gradle, пустой `catch`, `local.properties`/секреты в git, `TODO()`, наличие `gradle-wrapper.jar`.

Добавить:

- `assertTrue(true)` и подобные пустые тесты;
- `/* TODO */` и `TODO` в `app/src/main` (в UI не должно быть кнопок-заглушек);
- любые `am start`/`adb shell` в `scripts/` и `docs/` с пакетом без `.debug` (debug-пакет: `com.chromecore.camera.debug`);
- каждому `*.frag` соответствует запись в реестре эффектов и наоборот;
- каждая строка в `strings.xml` есть в `values-ru` и `values` (RU основной, EN запасной);
- упоминание в README/docs пакетов и классов, которых нет в коде (простая проверка по списку имён из `docs/ARCHITECTURE.md`);
- `chmod +x gradlew` в CI и `git update-index --chmod=+x gradlew`; добавь `gradlew.bat` (сгенерируй `gradle wrapper --gradle-version 8.9`).

### 4.3 Диагностика приложения (на этапе S1)

- `CrashHandler`: необработанное исключение → файл в `Documents/ChromecoreX/diagnostics/crash-<время>.txt` (стек, версия приложения, модель, версии API, текущий режим/эффект, последние 200 строк внутреннего лога).
- Кольцевой внутренний лог (`AppLog`), теги по модулям, доступен в Device Lab → «Экспорт диагностики» (один zip: лог + capabilities JSON + последний краш). Пользователю достаточно нажать «Поделиться» — дальше ты читаешь файл сам.
- В debug: `StrictMode` (thread/vm policy, penaltyLog), watchdog кадров (если кадр шейдера > 50 мс 30 раз подряд — автоматически понизить качество и записать в лог).
- Каждый эффект при ошибке компиляции шейдера **не роняет приложение**: показывается «Эффект недоступен», лог пишется, эффект отключается.

### 4.4 Тесты

- Unit: математика параметров фильтров, компилятор графа нод → GLSL (строка на выходе), сериализация пресетов (round-trip JSON), цикл режимов вспышки, выбор камеры, формирование имени файла/пути MediaStore.
- Инструментальные (эмулятор): запуск без краша, права, шаттер → файл в `Pictures/ChromecoreX`, смена камеры, открытие настроек, открытие Fx-панели.
- Скриншот-тесты Compose для ключевых экранов (по возможности, после стабилизации UI).
- Для каждого найденного бага — сначала тест, который его воспроизводит, потом исправление.

### 5.1 Главное архитектурное решение: единый GL-конвейер (ADR обязателен)

Цель: то, что видно в превью, один в один попадает в фото и видео (WYSIWYG).

- **Вариант A (сначала проверь его):** CameraX `CameraEffect` + `SurfaceProcessor` (через `UseCaseGroup`) — эффекты применяются к Preview, ImageCapture и VideoCapture через один процессор. Проверь актуальную поддержку и ограничения в документации CameraX для версии, которую используешь.
- **Вариант B (запасной):** собственный GL-рендерер на `SurfaceTexture` от Camera2/CameraX с отдельными FBO-проходами и выводом в превью + энкодер (`MediaCodec`/`MediaRecorder` surface).
- Решение принимай прототипом на устройстве/эмуляторе, результат запиши в `docs/DECISIONS.md`.
- Фото с эффектом: захватить полноразмерный кадр, прогнать через тот же `FrameGraph` в offscreen-FBO, сохранить JPEG в MediaStore. Оригинал (без эффекта) опционально сохранять отдельно (настройка «Сохранять оригинал»).
- ML (лицо/руки/сегментация) работает на уменьшенном кадре (≈256–480 px по длинной стороне) в отдельном потоке, результаты интерполируются между кадрами; GL-часть никогда не ждёт ML.

### 5.2 Модель эффекта (всё данные, а не код — чтобы эффекты можно было комбинировать, сохранять и делиться)

```
EffectDescriptor {
  id, name(ru,en), category, version,
  passes: [ { shader, inputs, uniforms: { name: param(min,max,default,curve) } } ],
  needs: [ FACE, HANDS, SEGMENTATION, AUDIO ],     // что нужно из ML/сенсоров
  cost: LOW | MEDIUM | HIGH                         // для адаптивного качества
}
```

Эффект = набор GLSL-проходов + параметры + ссылки на ассеты. Пресет = выбранные эффекты + значения параметров. Всё сериализуется в JSON.

### 5.3 Формат пакета `.ccfx` (безопасный шеринг эффектов)

Zip: `manifest.json` (id, версия, автор, минимальная версия приложения, cost, needs), `graph.json` (проходы/ноды/параметры), `shaders/*.frag`, `assets/` (PNG, WebP/GIF, LUT, меши `.obj`/`.glb`). **Никакого исполняемого кода** — только шейдеры и данные; шейдеры валидируются на импорте (длина, запрещённые конструкции, тестовая компиляция с таймаутом).

## 6. ДИЗАЙН-СИСТЕМА И ИНТЕРФЕЙС — «OBSIDIAN CHROME»

### 6.1 Идентичность

Палитра уже в коде (`ChromecoreColors.kt`) — не меняй значения без ADR:

- Obsidian Black `#0A0A0C` — фон; Graphite `#1A1A1F / #2C2C33 / #3A3A42` — поверхности
- Chrome Silver `#C8CCD0`, Platinum `#D4D7DC`, Titanium Grey `#4A4A52`, Cold White `#F5F5F7` — текст/иконки
- Cyan Accent `#4DD0E1` — интерактивное; статусы: Success `#69F0AE`, Warning `#FFD740`, Error `#FF5252`

Запрещено: стекломорфизм, фиолетовые градиенты, неоновая каша. Разрешено и желательно: полированный металл, хромовые градиентные кольца (как у `ShutterButton`), тонкие 1 dp рамки графита, тихие отражения (медленный блик, бегущий по кольцу затвора при съёмке), чёткие индустриальные формы.

Типографика: `SansSerif`, тонкие заголовки с трекингом, цифры экспозиции — моно (`FontFamily.Monospace`). Язык интерфейса: русский (основной) + английский через строковые ресурсы. Никакого захардкоженного текста в Compose.

### 6.2 Раскладка главного экрана (видоискатель на весь экран, всё остальное «ложится» поверх)

```
┌──────────────────────────────┐
│ ⚙   ⚡   ⏱   ▭3:4   HDR    ⟳ │  верх: настройки, вспышка, таймер, формат, HDR, смена камеры
│                              │
│        видоискатель          │  тап = фокус (кольцо хрома), вертикальный свайп рядом = экспозиция,
│     (эффект виден вживую)    │  щипок = зум, двойной тап = смена камеры, свайп влево/вправо = следующий/пред. эффект
│                              │
│  0.6x  1x  2x  (линза/зум)   │
│ ─── FX-карусель (линзы) ───  │  горизонтальная лента эффектов как в Snapchat; тап по активному = съёмка
│ [🖼]    ( ◉ ШАТТЕР )    [FX] │  слева: превью последнего фото → галерея; справа: открыть Fx-панель
│   Фото  Видео  Pro  Fx  Ноды │  режимы
└──────────────────────────────┘
```

- **Fx-панель** (bottom sheet, 60% высоты): вкладки `Фильтры · Глитч · AR · Стикеры/GIF · Ноды`; сверху — слайдер интенсивности выбранного эффекта; кнопка «Кубик» (случайная вариация параметров); кнопка «Сохранить как пресет».
- Долгое нажатие на шаттер = видео; свайп вверх при записи = зум; удержание на эффекте = быстрый предпросмотр «до/после».
- Всё, что редко нужно (формат, таймер, сетка, HDR), прячется под «прогрессивное раскрытие».
- Анимации ≤ 200 мс, 120 Гц-дружественные; без блокирующих спиннеров — скелетоны/плавные появления.
- Доступность: `contentDescription` на всех кнопках, минимум 48 dp цель касания, контраст ≥ 4.5:1.
- Ландшафт и складывание не ломают UI (`configChanges` уже есть; не сбрасывай состояние при повороте).

### 6.3 Другие экраны

- **Редактор:** превью сверху, лента инструментов снизу (Кроп, Свет, Цвет, Кривые, HSL, Эффекты, Маски, Текст, Стикеры), «до/после» по удержанию, отмена/повтор бесконечные (список операций).
- **Галерея:** сетка из MediaStore (папка `Pictures/ChromecoreX` + «Все»), фильтр по типу, жест щипком меняет размер ячеек.
- **Ноды:** бесконечный холст, ноды-карточки в стиле хрома, провода тонкие циан, живое превью справа/снизу на кадре камеры.
- **Device Lab:** карточки камер (id, facing, sensor size, focal lengths, ISO/выдержка диапазоны, RAW/DNG, OIS, поддерживаемые Extensions), кодеки, GPU/GLES версия, термо-статус; кнопка «Экспорт JSON/диагностики».

## 7. ФУНКЦИИ ПО ОБЛАСТЯМ (каждая — отдельный этап с критерием PASS)

### 7.1 Камера (ядро)

- Фото/видео, фронт/тыл, **выбор объектива** (основная / ультраширик) если ОС отдаёт их как физические камеры (проверь `physicalCameraIds`/`CameraInfo` в Device Lab, не предполагай).
- Фокус по касанию (`FocusMeteringAction`), блокировка AE/AF по долгому нажатию, компенсация экспозиции слайдером.
- Зум: щипок, слайдер, быстрые кнопки 0.6/1/2 (по факту доступного диапазона).
- Вспышка: через `ImageCapture.flashMode` (OFF/ON/AUTO); фонарик отдельно для видео; для фронталки — экранная вспышка.
- Таймер 3/5/10 с, серийная съёмка, сетка (3×3, золотая спираль), уровень горизонта, форматы 4:3 / 16:9 / 1:1 / полный экран.
- HDR/Ночь/Портрет/Retouch через **CameraX Extensions** (`ExtensionsManager`), только если устройство сообщает поддержку; иначе пункт скрыт.
- Правильная ориентация снимка (`targetRotation` от `OrientationEventListener`), EXIF.
- **Pro-режим:** ISO, выдержка, фокус (ручной), баланс белого (K), EV; гистограмма, focus peaking, zebra; RAW/DNG, если Camera2 сообщает `RAW` capability (через `Camera2Interop`).
- Голосовой шаттер («чиз»/«снимаю») и жесты рукой (открытая ладонь = таймер, «щипок» = шаттер) — флаги, по умолчанию выключены.

### 7.2 Фильтры и эффекты (живые, в GLSL)

Встроенные пресеты (минимум 30 к релизу, 10 на первый заход):

- **Хром-линия:** Liquid Chrome (рефлективный металл + шум-деформация), Metalheart, Mercury, Titanium Mono.
- **Кино:** Teal & Orange, Kodak-подобная плёнка, Bleach Bypass, Noir, Cross-process (+ зерно, виньетка, halation).
- **Ретро:** VHS (дрожание, tracking-шум), CRT (scanlines, кривизна, RGB mask), Polaroid, 8-мм плёнка.
- **Глитч:** RGB Split, Datamosh-подобные блоки, Pixel Sort (приближённая реалтайм-версия), Slice-shift, Signal Loss, Scanlines.
- **Пиксель/символы:** Pixelation, Dithering (Bayer/Floyd-подобный), ASCII-камера, Halftone, Mosaic.
- **Время/пространство:** Feedback/Trails (след), Echo, Slit-scan (по возможности), Mirror/Kaleidoscope.
- **Свет:** Bloom, Glow, Light Leaks, Lens Flare, Anamorphic streaks.
- **Цвет:** LUT-движок (импорт `.cube` и PNG-LUT 512×512 / 64³), HSL-микшер, кривые.

У каждого эффекта: параметры (минимум «интенсивность»), `cost`, превью-миниатюра для карусели (генерируется на лету из кадра, кэшируется).

### 7.3 AR: маски, стикеры, GIF (как в TikTok / Instagram / Snapchat)

Архитектура:

- **Лицо:** MediaPipe Face Landmarker (≈478 точек, blendshapes, матрица преобразования) — проверь актуальный пакет `tasks-vision`, размер модели, поддержку delegate GPU на Adreno 619. Запасной вариант — ML Kit Face Detection/Mesh. Выбор — по замеру FPS на устройстве, запись в ADR.
- **Руки:** MediaPipe Hand Landmarker (жесты, стикеры на ладони).
- **Сегментация:** MediaPipe Image Segmenter (selfie/person) → размытие фона, замена фона (картинка, видео, GIF), «хромовый человек» (эффект только на силуэт), портретный боке.
- **Якоря (`AnchorSystem`):** точки лица (лоб, нос, щёки, подбородок, уши), центр ладони; стикер хранит `anchor + смещение + масштаб + поворот` и следует за лицом с фильтром сглаживания (One-Euro) против дрожи.
- **2D-стикеры и ГИФки:** PNG/WebP/GIF/animated WebP. Декодирование анимации (Coil с GIF/animated-WebP декодером или `ImageDecoder` на API 28+ — выбери по minSdk 26 и замерам), кадры в GL-текстуры с лимитом памяти (атлас или кольцевой кэш), воспроизведение синхронно со временем. GIF можно: поставить на лицо, закрепить в кадре (тянуть, вращать, масштабировать жестами), использовать как фон.
- **3D-маски:** меш лица (канонический меш MediaPipe) с текстурой/PBR-материалом + аксессуары (очки, рога, шлем) в формате `.glb`/`.obj`; рендер в GL с матрицей из Face Landmarker. Эффект «хромовое лицо» (Metalheart): окружающая карта (environment map) из самой камеры, размытая, как отражение.
- **Внешние каталоги GIF/стикеров** (GIPHY, Tenor и т.п.): ТОЛЬКО по доступности и условиям на момент работы (проверь в интернете актуальность API и лицензий, некоторые сервисы закрываются или требуют ключ). Ключи — не в git, а в `local.properties`/GitHub Secrets. По умолчанию — локальная библиотека + импорт из галереи/файлов.
- Лимиты: лицо ≤ 2, руки ≤ 2, стикеров на кадре ≤ 8, суммарная память текстур ≤ 128 МБ (настраивается), всё сверх — отбрасывается без падения.

### 7.4 Нод-движок (стиль TouchDesigner)

- Граф: `Source (камера) → … → Output`. Типы нод: Фильтры (Blur, Sharpen, Levels, Curves, LUT, HSL), Искажения (Displace, Ripple, Kaleidoscope, Mirror), Глитч (RGB Split, Slice, PixelSort, Dither, Pixelate, Scanlines), Генераторы (Noise, Gradient, Pattern), Смешивание (Mix, Blend modes, Mask), Время (Feedback, Delay, Echo), AR (Face Anchor, Segmentation Mask, Hand Position), Сигналы (LFO, Random, Audio FFT, Touch XY, Accelerometer).
- **Реагирование на звук:** микрофон → FFT (низ/середина/верх) → управляет параметрами (бас дергает RGB-split, голос меняет цвет). Работает только после явного разрешения микрофона.
- `GraphCompiler` превращает граф в цепочку GLSL-проходов с объединением (fusion) соседних простых нод в один проход для скорости; результат — строка шейдера, которую можно протестировать юнит-тестом и прогнать через `glslangValidator`.
- Живое превью на камере; сохранение графа как пресет или `.ccfx`.
- Кнопка «Кубик»: случайная, но «красивая» мутация параметров (диапазоны безопасных значений в дескрипторах).

### 7.5 Таймлайн-слои (стиль After Effects) — после нод

- Слои: видео/фото, текст, GIF/стикер, эффект-слой (корректирующий), форма.
- Ключевые кадры на параметрах (линейная/ease/bezier), режимы смешивания (Normal, Add, Multiply, Screen, Overlay, Difference), маски, трекинг объекта (опора на landmarks/оптический поток — по возможности).
- Экспорт в MP4 (H.264/HEVC по поддержке) через `MediaCodec` с тем же GL-конвейером.

### 7.6 Редактор

Неразрушающий (хранится список операций, оригинал не меняется): экспозиция, контраст, света/тени, баланс белого, насыщенность/вибранс, резкость, шум, виньетка, зерно, кривые, HSL, кроп/поворот/выравнивание, LUT, эффекты (те же, что на камере), локальные маски (кисть/градиент), текст, стикеры/GIF поверх, экспорт JPEG/HEIC/PNG, сохранение «проекта» для повторного редактирования.

### 7.7 Вычислительная фотография (позже, но заложи в архитектуру)

Мультикадровый HDR/ночь (серия → выравнивание → слияние), подавление шума, super-res, портрет с боке — на LiteRT (проверь актуальные названия/версии пакетов TFLite/LiteRT) или CameraX Extensions там, где они есть. Модели `*.tflite` не в git (см. `.gitignore`), а скачиваются или лежат в `assets` с проверкой размера.

### 7.8 Видео

`VideoCapture` CameraX, запись со звуком, живые эффекты в записи, стабилизация (если поддерживается), замедленная/ускоренная, режимы 1080p30 / 4K по реальным capabilities (не по спецификации из интернета), быстрая пауза, фото во время записи, экспорт с эффектами из редактора.

## 9. СУПЕР-ИДЕИ (брать по одной, после ядра; каждая через флаг)

1. **Metalheart Mode:** лицо/руки/силуэт превращаются в жидкий хром с отражением реального окружения.
2. **Glitch Director:** кнопка «Кубик» собирает случайный, но красивый глитч-рецепт и показывает на кадре; «Заморозить» сохраняет рецепт в пресет.
3. **Audio-reactive камера:** музыка в комнате управляет эффектами; режим «концерт».
4. **Gesture shutter:** ладонь — таймер, «пистолетик/щипок» — съёмка, кулак — старт записи.
5. **Dual-cam PiP:** фронталка и тыл одновременно, картинка в картинке, маски на одном из потоков.
6. **Boomerang / Loop / Live-фото:** 2-секундный зацикленный клип с эффектом, экспорт в GIF/MP4/WebP.
7. **Light Painting / Long Exposure:** накопление кадров, следы света (астро-режим, трассеры).
8. **Smart scene hint:** на основе гистограммы/сегментации подсказывать подходящий эффект («тёмная сцена → Night, лицо → Retouch»).
9. **Effect Remix:** выбрал эффект друга (`.ccfx`) → нажал «Ремикс» → мутация параметров.
10. **QR-обмен эффектами:** показать QR (ссылка/маленький `.ccfx`), отсканировал на другом телефоне — эффект в камере.
11. **ASCII / Thermal / Anaglyph 3D / Depth fog** как быстрые «вау»-фильтры.
12. **Edit-from-camera:** долгий тап по превью в галерее → «Открыть в Fx» — эффекты редактора = эффекты камеры, один движок.
13. **Теневой оригинал:** всегда можно «снять без эффекта» после съёмки (оригинал хранится рядом, если включено).
14. **Device Lab «Сертификат камеры»:** отчёт «что реально умеет ваш телефон» + авто-отключение того, что не поддерживается.
15. **Скрипт демо-кадров для CI:** виртуальная сцена + эталонные кадры для регрессии эффектов (сравнение с допуском).

## 10. БЮДЖЕТ ПРОИЗВОДИТЕЛЬНОСТИ (Adreno 619, 8 ГБ)

- Превью: цель 30 FPS при 1080p с ≤ 3 GL-проходами; 60 FPS — режим без тяжёлых эффектов. Тяжёлые эффекты (`cost: HIGH`) разрешены на 720p-внутреннем разрешении с апскейлом.
- ML: лицо/руки/сегментация ≥ 15–20 Гц на малом кадре, не блокируя GL; результаты экстраполируются.
- Память: пул FBO (не создавать на каждый кадр), пул `Bitmap`, лимит текстур стикеров/GIF, `largeHeap` не лечит утечки.
- Термо: слушать `PowerManager` thermal status (API 29+); при `MODERATE+` автоматически понижать разрешение/FPS эффектов и показывать мягкую иконку; при `SEVERE` отключать ML.
- Измерения: кадровое время (GPU timer queries там, где поддерживается), Perfetto/`dumpsys gfxinfo` в эмуляторе/на устройстве; запись цифр в `docs/PERF.md` по каждому этапу S3+. Нет цифр — нет PASS.
- Никаких аллокаций в кадровом цикле (проверь на этапе S3 через профилировщик).

## 15. РЕЖИМ «НИЧЕГО НЕ СЛОМАТЬ»

### 15.1 Волны и ветки
- Эффекты добавляются волнами по ≤ 8 штук. Одна волна = одна ветка/PR → зелёный CI → merge в рабочую ветку. Красное в рабочую ветку не попадает.
- На каждый зелёный коммит рабочей ветки ставь git-тег `green-<run id>`. Если что-то сломалось и быстро не чинится — откат к последнему `green-*`, а не латание на красной ветке.
- Каждая волна за feature-флагом `FX_WAVE_<буква>`; включается по умолчанию только после PASS волны.
- Общие части (GL-конвейер, реестр, тема, навигация) меняются отдельным этапом с полным прогоном всех тестов эффектов.

### 15.2 Автотесты каждого эффекта (в CI, обязательно)
Для КАЖДОЙ записи реестра автоматически (параметризованный тест, перебирает весь реестр):
1. Шейдеры проходят `glslangValidator`.
2. На тестовом изображении (шахматка + градиент + цветные плашки + «лицо» из ассета) при `intensity = 0` результат ≈ входу (макс. отклонение ≤ порога).
3. При `intensity = 1` результат отличается от входа (иначе эффект «пустой»).
4. Нет NaN/Inf, нет полностью чёрного/белого кадра (если это не задумано).
5. Размер выхода = размеру входа; параметры в заявленных min/max не дают краша.
6. Записать время прохода на эмуляторе в отчёт (только для сравнения между коммитами, не как оценка FPS).
Каталог ↔ реестр ↔ файлы шейдеров ↔ строки локализации — сверяет preflight (§4.2).

### 15.3 Защита во время работы приложения
- **Карантин эффектов:** ошибка компиляции/рендера эффекта → он отключается, попадает в `QuarantineStore`, в UI показан серым с подписью «недоступен на этом устройстве», приложение продолжает работать, причина в `AppLog`.
- **Safe Mode:** если приложение упало ≥ 2 раз за 60 секунд после старта — следующий запуск без эффектов/ML (чистая камера) и с баннером «Безопасный режим». Кнопка «Выйти из безопасного режима».
- **Адаптивное качество:** FPS ниже порога N секунд → понизить внутреннее разрешение/отключить `cost: HIGH`, записать в лог. Перегрев → то же (§10).
- **Прогон всех эффектов** (Device Lab → «Проверить все эффекты»): по очереди включает каждый эффект на 1 с на живой камере, считает кадровое время, помечает проблемные, сохраняет отчёт. Пользователь жмёт одну кнопку и делится файлом — ты разбираешь сам.

### 15.4 Что запрещено при добавлении эффектов
Копировать шейдер «как есть» без проверки лицензии; добавлять эффект без записи в реестр/теста; отключать тесты, чтобы «прошло»; ставить статус «сделано» без CI-run.

## 16. «ЛЮБЫМ СПОСОБОМ» — ЧТО ЭТО ЗНАЧИТ

Разрешено и поощряется: искать в интернете, читать документацию и исходники библиотек, делать прототипы в отдельной ветке, портировать алгоритмы из статей, использовать библиотеки с лицензиями Apache-2.0/MIT/BSD, писать собственные шейдеры, генерировать текстуры и LUT процедурно, менять подход, если первый не работает (например, перейти с `CameraEffect` на собственный GL-рендерер).

Нельзя: обходить правила §2 (фальшивая зелень, отключение проверок), брать код/ассеты с неподходящей лицензией (GPL, Non-Commercial; у Shadertoy-шейдеров лицензия по умолчанию некоммерческая — проверять в каждом), чужие платные LUT-паки и ассеты Snap/TikTok, пакеты без проверки происхождения, скрытую телеметрию. Если «единственный способ» требует нарушить это — напиши пользователю, предложи альтернативу.
